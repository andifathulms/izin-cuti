# Isi Surat

**Map an office form once, fill it in six fields forever. Your document never leaves your device.**

A client-side docx template mapper and filler. Upload a Word form as it is —
no placeholders, no `{nama}` tokens, no rewriting — mark the fields that vary,
and fill it from a short form after that.

Static site. No backend, no accounts, no runtime network, nothing transmitted.

---

## Why

Indonesian office life runs on Word forms. A cuti request has around thirty
fields, most of them the same every time: your name, your NIP, your jabatan,
your atasan's name and NIP. You retype them, or you copy last month's file and
edit it, and eventually you submit one with last month's dates still in it.

Word cannot tell you that the letter date is a year before the leave, that you
asked for three days against a two-day balance, or that your NIP is seventeen
digits. This can.

## How it works

```
your .docx
  → unzip, in memory
  → read word/document.xml → text nodes + empty cells, each with its context
  → you mark and name the ones that vary        (once, per template)
  → fill: substitute text, insert checkmarks    (every time, six fields)
  → re-zip → download
```

Only `word/document.xml` is ever modified. Every other part of the package —
fonts, images, styles, relationships — is copied through byte for byte.

## The five things that shape everything

1. **A silently mis-filled official form is the worst thing this can produce.**
   Every mapping carries a fingerprint of its template. A changed template is
   refused, with the differences named. There is no "fill anyway".
2. **Escaping is mandatory.** An address with `&`, a name with `<` — unescaped,
   these produce a file Word refuses to open. Every substituted value passes
   through one escape function, and the suite carries twenty hostile values
   permanently.
3. **Nothing leaves the device.** There is no server, so this is structural
   rather than a policy — and it is said where you are typing your NIP.
4. **Only `word/document.xml` is modified.** Asserted by test.
5. **DOCX is authoritative; PDF is approximate.** Faithful docx-to-PDF needs a
   rendering engine and cannot be done in a browser. The app says so wherever
   the two appear together.

## Privacy

Name, NIP, home address, telephone, reason for leave. None of it is uploaded,
stored remotely, transmitted, or measured. The document is read into memory,
filled, and downloaded locally.

Profiles and mappings live in this browser's local storage, with an explicit
export and clear-all on the profile page.

The template is not stored unless you ask it to be. Because your office form
arrives with a real person's real data in it, map mode can produce a **blank
copy** — every mapped value replaced by its field name, not a byte of
structure changed — and that is what is safe to keep. Blanking it in Word
instead would restructure the text runs and break the mapping. Once
remembered, the app shows the date, and reminds you that a remembered
template never updates when your office reissues the form.

No analytics. No error reporting. No third-party script of any kind. Fonts are
self-hosted.

## Not this

No approval workflow, no submission, no routing. No digital signature. **No
nomor surat generation** — a shared sequential number is shared state, so the
number is an input. No bundled government templates: you supply your own, which
keeps the app generic and keeps official documents out of a public repository.

## Development

```bash
pnpm install
pnpm dev

pnpm test:run        # everything
pnpm test:escape     # XML-special characters       ┐
pnpm test:roundtrip  # fill → re-parse → values match │ these three gate the build
pnpm test:package    # zip integrity, byte-identical passthrough ┘
pnpm test:drift      # fingerprint detection, both directions

pnpm typecheck
pnpm lint
pnpm build           # static export to ./out
pnpm preview         # serve ./out under the production basePath
```

`lib/docx` is pure: bytes in, bytes out, no DOM, no React, no clock, no
network. That is what makes the round-trip suite possible, and the round-trip
suite is what everything else rests on.

Test fixtures are synthetic documents generated by the suite. **No official
template ships in this repository** — not in fixtures, not in examples, not
here.

To produce a sample output and open it in a real word processor:

```bash
npx tsx scripts/make-sample.mts sample.docx
```

## Deployment

`main` builds and deploys to GitHub Pages via Actions, gated on the suites
above. `basePath` must match the repository name — it is taken from
`BASE_PATH` in CI and defaults to `/izin-cuti` — and `.nojekyll` must exist in
`out/`. Verify with `pnpm preview` before pushing.
